# Benchmark Evidence Plan

## Summary

Make the next task release evidence: finish the last VM proof reporting gap,
generate current benchmark data, and update docs so the completed known-tester
work has measurable proof attached.

## Current Status

- Dashboard evidence output is implemented in `guix-p2p-e2e vm fetch`.
- Provider lookup now collects and deduplicates a short burst of matching DHT
  provider notifications before handshakes, so stale provider records do not
  immediately exclude newer seeders.
- P2p-only `info` replies now return verified narinfo metadata without DHT
  gating; availability is enforced by `have` and the final `substitute`
  request, so Guix dependency metadata checks do not stall the VM proof.
- Strict VM proof rerun passed for `hello` and printed dashboard evidence.
- Minimal p2p-only benchmark evidence now passes for `hello` with a fresh base:
  `cargo run -p guix-p2p-e2e -- benchmark --packages hello --modes p2p-only
  --iterations 1 --transport tcp --keep-temp --base target/guix-p2p-bench-rerun`.
- The container benchmark now resolves the raw `guix-daemon`, reaches the
  generated relay wrapper, performs an explicit p2p-only substitute restore, and
  leaves `manual-substitute-output` in the kept run directory for manual
  inspection.

## Key Changes

- Add dashboard evidence output to the VM proof path.
- Extend `guix-p2p-e2e vm fetch` to print seed-node `/api/seeds` evidence and
  fetch-node `/api/catalog` evidence after a successful import.
- Print the matching seed/catalog entries for the fetched target, plus counts.
- Skip dashboard evidence with a clear message only when dashboard forwarding
  is disabled.
- Run the benchmark harness with current defaults:
  - packages: `hello,git,emacs`
  - modes: `http,p2p-only,p2p-first`
  - iterations: `3`
  - transport: `tcp`
- Keep benchmark output at `target/guix-p2p-bench/results.csv` and
  `docs/benchmark-results.md`.
- Update `docs/e2e.md` to note that the VM proof prints dashboard seed/catalog
  evidence.
- Update `docs/implementation-plan.md` to mark VM dashboard evidence and
  performance benchmarking complete only after successful runs.
- Let `docs/benchmark-results.md` be generated by the benchmark harness.
- Keep the p2p-only benchmark container using the host Guix command revision so
  the resolved package and seeded store path match.
- Seed and announce all runtime closure outputs before starting the isolated
  build daemon.
- Use `local_narinfo_path` benchmark metadata so p2p-only provider lookup does
  not depend on external narinfo fetches for locally seeded closure paths.
- Resolve raw `guix-daemon` from the host launcher so the generated `GUIX`
  wrapper is not overwritten by the launch script.
- Do not advertise daemon-runtime paths as p2p benchmark substitutes; these may
  be exposed read-only for the isolated daemon itself.
- Add a direct relay substitute verification step in p2p benchmark modes. This
  compensates for shared-store container no-op builds and records block-serving
  evidence plus a restored `manual-substitute-output` tree.
- Allow `--min-providers` as a CLI override so two-node benchmark runs can set
  the provider threshold explicitly.
- Let unknown-size local narinfo entries use handshake block counts and final
  NAR hash verification during p2p downloads.

## Assumptions

- Keep the benchmark scope at the repository defaults.
- Do not start bootstrap-node deployment or Guix channel packaging in this task.
- Shared-store containers can make exact store-path builds no-op if the host
  already has the output. The benchmark therefore also runs an explicit relay
  substitute restore for p2p modes and uses that for block-serving evidence.
- If a kept temp directory contains container-owned files, rerun with a fresh
  `--base` instead of deleting the evidence directory.
- Make one Conventional Commit after code, docs, and verification are complete.
